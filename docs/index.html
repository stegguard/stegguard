A safer workflow

From untrusted input to reviewable evidence.

StegGuard keeps inspection and modification separate. Scan first, decode recognized channels without changing the source, sanitize a copy, and verify the result.

STEP // 01

Scan a single file or recurse through a directory for hidden-content and provenance signals.

STEP // 02

Inspect

Review severity, byte offsets, suspicious characters, structural evidence, and incomplete checks.

STEP // 03

Sanitize

Write a separate sanitized file by default. Originals change only with explicit confirmation.

How classification works

Evidence classification, not an AI verdict.

StegGuard primarily uses deterministic parsers, explicit rules, format-aware checks, and documented statistical signals. Optional analyzers or official verifiers are used where a keyed or vendor-specific scheme cannot be evaluated generically.

01 // ROUTE

Identify the input path

The filename, extension, signature, and container structure select text, binary, image, audio, document, or provenance checks.

02 // OBSERVE

Collect independent evidence

Detectors record category, detector name, description, confidence, location, evidence, and risk rather than collapsing everything into one opaque score.

03 // AGGREGATE

Calculate report severity

Hidden-character counts, whitespace findings, mixed endings, LSB suspicion, and risky watermark or provenance results determine the displayed severity.

04 // COMPLETE

Preserve uncertainty

Unsupported or unavailable verification is reported as incomplete or NOT_CHECKED. It is never silently converted into a clean result.

Report severity
CLEAN

The completed checks found no actionable signal.

LOW

A small or informational signal is present.

MEDIUM

Multiple or stronger indicators warrant investigation.

HIGH

Strong aggregate evidence, suspicious LSBs, or risky provenance needs attention.

CRITICAL

The aggregate detector score crosses the highest review threshold.

Result states

Confidence and status answer different questions.

A finding's confidence expresses the strength of that detector's evidence. Validation status records whether provenance or a specialized watermark was actually checked.

DETECTEDThe configured detector found matching evidence.
NOT_DETECTEDThe applicable check ran without a positive result.
NOT_CHECKEDNo suitable analyzer or verifier was available.
VALIDProvenance passed cryptographic validation.
TAMPEREDValidation indicates an integrity failure.
A clean result is not proof that a file is safe or human-made. Detection is limited to supported formats, configured analyzers, resource budgets, and known signal families. Keyed or proprietary watermark schemes require their corresponding verifier.
Quick start

Install. Scan. Generate evidence.

StegGuard requires Python 3.12 or newer. Use the package release when available, or install the current source checkout for development and evaluation.

Install StegGuard

Install from PyPI when a release is available, or work from the repository source.

PyPI release
python3 -m pip install stegguard
From source
git clone https://github.com/stegguard/stegguard.git
cd stegguard
python3 -m pip install -e .

Run a detection scan

Scan one file, or point StegGuard at a directory and add -r for recursive discovery.

Single file
stegguard detect suspicious.py
Recursive directory
stegguard detect ./repo -r

Generate the HTML report

Use --html for a standalone visual report. Add --json when an automated consumer needs the same scan.

HTML + JSON
stegguard detect ./repo -r --json findings.json --html report.html
Open the generated report
python3 -m webbrowser report.html

Report watermark and provenance evidence

Analyze watermark, fingerprint, and provenance signals with dedicated JSON and HTML output.

Watermark report
stegguard watermark image.png --json watermark.json --html watermark.html
Validate Content Credentials
stegguard watermark image.png --c2pa-tool c2patool --html provenance.html
